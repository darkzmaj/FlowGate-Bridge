# Maintenance audit — 2026-10-16

Reviewed the complete original Java implementation, configuration, plugin metadata, build settings, wrapper, README, license, default branch, tags and open PRs. Confirmed target case corruption, stale command mappings after reload, missing owned-command/channel cleanup, permissive route parsing, fragile command registration and lack of rate control. Current Paper runtime testing additionally exposed unsupported iterator removal in its command-map view, fixed by removing owned keys.

Security boundary: commands may encode only the configured target using the fixed Bungee Connect format for the executing Player. There is no console execution, arbitrary command forwarding or incoming plugin-message handler. Routes reject unsafe names and non-string values. Existing default access is preserved through a default-true permission, while admins can explicitly deny use. Backend/proxy transport is trusted infrastructure and still requires firewall and forwarding configuration. No telemetry, tracking or external service was added.

Unit tests cover exact UTF framing/case, control characters/oversized names/command-like payload rejection, locale-independent command normalization, malformed/colliding routes and intentional empty route configuration. Local integration exercises actual Minecraft protocol 777, Paper 26.3 backends and proxy connection switching, command reload/removal and invalid reload rollback. Verified proxy paths: BungeeCord build 2104 with FlowGate Lite, and Velocity 4.2.0 build 30 with the Bungee plugin-message channel enabled (legacy forwarding in the isolated test). Both tests rejected a forged client-originated Connect payload and completed a real server switch. No claim is made for online authentication, older platform versions, Folia, vanilla Spigot, Citizens integration, delivery acknowledgments or high-load behavior.

The build uses the stable Paper API 26.3.build.194-stable. API dependencies remain compile-only and are provided by the server; the distributable bundles no third-party runtime code. JDK 25 builds Java 21 plugin bytecode. Metadata remains api-version 1.21, preserving the existing baseline. Current Paper 26.3 requires Java 25.
